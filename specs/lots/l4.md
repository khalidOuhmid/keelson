# Lot L4 — toolchain

Cadrage écrit depuis `main` à `36caaa1`, sur le code réel.

## 1. Constats sur l'existant

- `packages/toolchain` ne contient que `parseLayout` ; `core` n'a aucun type de toolchain.
- Les fiches `kind: service` ont des `detect.scripts`, mais rien ne dit le type d'intégration.
- Le store du serveur ne connaît que les fichiers CI du workspace. `.devsecops/layout.json` n'est
  jamais écrit. `writeAtomic` suppose le dossier présent.
- `store.applyOperation` écrit sans relire le disque : une écriture externe de moins de 40 ms est
  écrasée (écart du 2026-11-04). Tout écrivain de L4 passe par le même chemin : corrigé en tête.
- Écart du 2026-11-04 : `scm` n'est jamais couvert, faute de `detect` sur gitea, github et gitlab.
  Un service déclaré le couvre désormais.

## 2. Décisions

- **D1 — fichier.** `.devsecops/toolchain.yaml` : `version: 1`, `services` (map par identifiant :
  `tool`, `url`, `environment`), `integrations` (liste `job`, `service`, `kind`), `dismissed` (liste
  `job`, `tool`, `kind`). ADR 0009.
- **D2 — écriture.** Patch en place par plages de nœuds, comme `adapter-gitlab` : commentaires et
  ordre survivent, inverse `splice`. Une section en flow non vide est refusée, pas réécrite.
- **D3 — inférence.** Une fiche `service` déclare `integration`. L'inférence rend des propositions
  `(job, tool, kind)`, jamais écrites toutes seules. Le fichier confirme par `integrations`, écarte
  par `dismissed`. ADR 0010.
- **D4 — couverture.** Un service déclaré couvre les couches de son outil. ADR 0011.
- **D5 — positions.** `positions` dans `layout.json`, par nœud. Réécriture du JSON à clés triées qui
  garde les clés inconnues, refusée si le fichier est illisible : Keelson n'écrase pas ce qu'il ne
  comprend pas.
- **D6 — diagnostics.** `validate` et l'API les rendent ensemble. Un job inconnu est une erreur sur
  un pipeline complet, un warning sur un pipeline partiel : le job peut venir d'un include distant.

## 3. API

```ts
// @keelson/core
type Service = { id: string; tool: string; url: string | null; environment: string | null };
type IntegrationKind = "push" | "upload-report" | "fetch-secret" | "notify";
type Integration = { job: string; service: string; kind: IntegrationKind };
type DismissedIntegration = { job: string; tool: string; kind: IntegrationKind };
type Toolchain = { services: Service[]; integrations: Integration[];
                   dismissed: DismissedIntegration[] };
type ToolchainOperation = addService | updateService | removeService | addIntegration
                        | removeIntegration | dismissIntegration | restoreIntegration | splice;
parseToolchainOperation(raw);
// @keelson/toolchain
parseToolchain(text | null): { toolchain, diagnostics };
validateToolchain(toolchain, pipeline, tools): Diagnostic[];
applyToolchain(text, operation): Result<{ text, hash, toolchain, inverse, touched }>;
resolveIntegrations(pipeline, toolchain, tools): { declared, proposed };
// @keelson/catalog
detectIntegrations(signals, tools): { tool, kind }[];
```

Routes, même garde que les documents :

| Méthode | Route | Réponses |
|---|---|---|
| GET | `/api/toolchain` | 200 `{ text, hash, toolchain, diagnostics, proposed, positions }` |
| POST | `/api/toolchain/operations` | `{ op, opId }` → 200 le même corps plus `inverse` · 400 · 409 · 422 |
| PUT | `/api/layout/positions` | `{ positions }` → 200 · 400 · 422 si `layout.json` est illisible |

SSE : `toolchain.changed { hash }`.

## 6. Définition de terminé

1. Services et intégrations lus, validés, écrits par opérations inversables, commentaires conservés.
2. Quatre propriétés fast-check sur un corpus de fichiers, à 500 runs.
3. Inférence : proposée, confirmée, écartée, jamais écrite seule.
4. Vue Toolchain : graphe, positions libres persistées, panneau équivalent au clavier, DOM et E2E.
5. `keelson validate` couvre la toolchain ; `keelson coverage` compte les services.
6. Écarts du §4 clos avec preuve.
7. `shape`, `critique`, `audit`, `polish`, `document` si les tokens changent.
8. Revue indépendante, contre-revue, vérification complète, fusion, journal.
