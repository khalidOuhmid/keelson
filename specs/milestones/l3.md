# Milestone L3 — taxonomy, catalogue, OWASP overlay

Scoping written from `main` at `125ccc8`, on the real code.

## 1. Findings on the existing code

- `packages/taxonomy` and `packages/catalog` only export `PACKAGE_NAME`. `catalog/tools` and
  `catalog/logos` are empty.
- The IR carries neither `image` nor `script`: they are opaque blocks. Detection therefore cannot
  happen there without an addition to the IR.
- `keelson coverage` is a dated debt in `cli/src/run.ts`; `catalog lint` does not exist.
- The OWASP Guideline (<https://github.com/OWASP/DevSecOpsGuideline>, CC BY-SA 4.0) no longer
  enumerates thirteen layers in that form: `current-version/` is organised under `2-Process`. **The
  13 layers are therefore a Keelson projection**: each points to its section, and no Guideline text
  is copied, only topic names, summarised in our own words.

## 2. Decisions

- **D1.** `Job.signals: { image: string | null; script: string[] }`, effective values after
  `extends`, includes and `default:`. The IR stays provider-neutral: L6 will add `uses` and `run`.
- **D2.** The catalogue lives in YAML, one file per tool. `bun run catalog:build` produces
  `packages/catalog/src/generated/catalog.json`, logos included, committed and checked by a test:
  the binary embeds the catalogue without depending on the disk, and `simple-icons` stays a
  devDependency.
- **D3.** Coverage is computed on the server side, in `@keelson/catalog`, so that the CLI and the UI
  say the same thing. The UI receives `coverage` in the document payload, and `GET /api/catalog`.
- **D4.** `.devsecops/layout.json`: `{ "version": 1, "layers": { "<job>": ["sast"] } }`. An entry
  **replaces** the job's detection, an empty list neutralises it. Read by `@keelson/toolchain`,
  watched by the watcher. L4 will add positions.
- **D5.** The catalogue is a data contract, not free text: `detect` contains regexes compiled at
  lint time, and `snippets` YAML checked at parse time.
- **D6.** A covered layer claims nothing about quality: "a job matches a tool of this layer". A
  partial pipeline makes coverage a **lower bound**, stated on screen and in the CLI.

## 3. API

```ts
// @keelson/taxonomy
type Layer = { id: LayerId; name: string; short: string; family: LayerFamily;
               source: "owasp" | "platform"; summary: string; guideline: string | null };
// @keelson/catalog
loadCatalog(): Catalog; lintCatalog(files, logos, now);
detectTools(signals, tools); coverage(pipeline, tools, overrides, parsing): Coverage;
// @keelson/catalog/licenses, without zod or yaml, for the UI bundle
isOpenSource(license);
// @keelson/toolchain
parseLayout(text | null, pipeline): { overrides, diagnostics }
```

CLI: `keelson coverage [file] [--require a,b] [--format text|json]` (1 if a required layer is
missing or if the YAML is unreadable, 2 if a requested layer does not exist); `keelson catalog lint
[folder]` (1 on an error, 0 on a mere freshness notice).

## 6. Definition of done

1. 21 layers, 13 OWASP + 8 platform, each with its source.
2. 50 to 100 tools, at least two per OWASP layer including one open source, the nine mandatory ones
   present, each catalogue entry with its verification URL.
3. Detection and override tested, including through an include.
4. Overlay, uncovered-layers panel, Catalogue view, tool entry: tests on the rendered DOM and E2E.
5. `keelson coverage` and `keelson catalog lint` conform to §3.
6. Gaps of §4 closed with proof.
7. `shape`, `critique`, `audit`, `polish`, `document`.
8. Independent review, counter-review of the fixes, full verification, merge, log.

## 7. Interface scoping (`/impeccable shape`)

**Operate** mode. The audience that changes is the security architect: they read, they do not
edit.

- **Three views in the header**: Pipeline, Coverage, Catalog. Coverage is the **reading posture**:
  editing controls disappear, the left sidebar becomes the list of layers.
- **Overlay**: each job carries layer labels, with their word, never colour alone. Twenty-one hues
  would be illegible: colour carries the **family** (Build, Test, Operate, Platform), three new
  tokens, the platform staying neutral.
- **Uncovered layers**: at the top of the sidebar, each layer gives its summary, its Guideline
  section when it has one, and "See tools", which opens the filtered catalogue.
- **Lower bound**: partial pipeline, the sidebar says "Coverage is a lower bound".
- **Catalogue**: dense table filterable by layer, licence and adapter; entry on the right with
  licence, verification source, layers and read-only snippets.
- **Width**: below `lg`, the detail panel becomes an overlay and the left sidebar opens on demand.
  This is a deliberate exception to the "no breakpoints" rule of `DESIGN.md` (ADR 0008).
- **Included job**: `JobEditor` is no longer mounted, `JobDetailPanel` states the reason.
