# Milestone L5 — proposals and insertion

Scoping written from `main` at `b12493b`, on the real code.

## 1. Findings on the existing code

- `addJob` writes `stage`, `needs`, `environment` and `script`: a snippet also carries `image`,
  `entrypoint` or `variables`, which it cannot write.
- An inverse is already a single `splice`, but `apply` composes nothing.
- The tool entry displays the snippet read-only. `See tools` already leads there from a layer.
- `keelson export` is a dated debt.
- Gap of 2026-11-04: overriding inherited `needs` loses cross-project needs, "to be addressed
  before L5". Addressed first.

## 2. Decisions

- **D1 — `addSnippet`.** New operation: `id`, `stage`, `snippet`. The snippet is the YAML of a
  single job, copied as is; only its key and its `stage` change. Any other shape is rejected.
- **D2 — `composite`.** `steps` are applied in sequence; the failure of one step rejects all of
  them. The inverse is a single `splice` and `touched` a single range: from the first to the last
  changed byte. ADR 0012.
- **D3 — preview.** `POST /api/documents/:file/preview` returns the result without writing, with the
  same rejections as an operation and the resulting coverage. A diff computed on the client, line by
  line, shows what will be written.
- **D4 — export.** `keelson export --format mermaid|markdown|json [file]`, on standard output,
  deterministic. Formats documented in `specs/export.md`.
- **D5 — detection.** Minimal shell tokenisation: quotes, comments, `bash -c`, `$(…)`, `sudo`. The
  rest of the 2026-11-04 gap stays open.

## 7. Interface scoping (`/impeccable shape`)

**Operate** mode. The autopilot rules out interactive validation: assumptions settled here. Visual
authority: `DESIGN.md`, with no new token.

- **Path**: Coverage, `See tools`, tool entry, `Add to pipeline`. The entry remains the only place
  where a tool is decided on: no second list.
- **In the entry**: job name, stage, diff, layer covered after insertion, `Insert`. The diff is
  reviewed before acting because that is how the user judges Keelson.
- **Diff**: lines marked `+` and `-`, the sign carries the meaning, colour reinforces it.
- **Rejection**: the preview states the rejection plainly and `Insert` stays disabled.
- **After**: back to the Pipeline view, job selected; `Undo` removes everything at once.
- **Absent**: a tool without a GitLab snippet says so. An invalid file disables insertion.
