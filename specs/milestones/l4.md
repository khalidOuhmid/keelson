# Milestone L4 — toolchain

Scoping written from `main` at `36caaa1`, on the real code.

## 1. Findings on the existing code

- `packages/toolchain` only contains `parseLayout`; `core` has no toolchain type.
- `kind: service` catalogue entries have `detect.scripts`, but nothing states the integration type.
- The server store only knows the workspace's CI files. `.devsecops/layout.json` is never written.
  `writeAtomic` assumes the folder exists.
- `store.applyOperation` writes without re-reading the disk: an external write less than 40 ms old
  is overwritten (gap of 2026-11-04). Every L4 writer goes through the same path: fixed first.
- Gap of 2026-11-04: `scm` is never covered, for lack of `detect` on gitea, github and gitlab. A
  declared service now covers it.

## 2. Decisions

- **D1 — file.** `.devsecops/toolchain.yaml`: `version: 1`, `services` (map by identifier: `tool`,
  `url`, `environment`), `integrations` (list of `job`, `service`, `kind`), `dismissed` (list of
  `job`, `tool`, `kind`). ADR 0009.
- **D2 — writing.** In-place patch by node ranges, like `adapter-gitlab`: comments and order
  survive, `splice` inverse. A non-empty flow-style section is rejected, not rewritten.
- **D3 — inference.** A `service` catalogue entry declares `integration`. Inference returns
  `(job, tool, kind)` proposals, never written on their own. The file confirms through
  `integrations`, dismisses through `dismissed`. ADR 0010.
- **D4 — coverage.** A declared service covers the layers of its tool. ADR 0011.
- **D5 — positions.** `positions` in `layout.json`, per node. The JSON is rewritten with sorted keys,
  keeping unknown keys, and refused if the file is unreadable: Keelson does not overwrite what it
  does not understand.
- **D6 — diagnostics.** `validate` and the API return them together. An unknown job is an error on
  a complete pipeline, a warning on a partial pipeline: the job may come from a remote include.

## 3. API

```ts
// @keelson/core
type Service = { id: string; tool: string; url: string | null; environment: string | null };
type IntegrationKind = "push" | "upload-report" | "fetch-secret" | "notify";
type Integration = { job: string; service: string; kind: IntegrationKind };
type DismissedIntegration = { job: string; tool: string; kind: IntegrationKind };
type Toolchain = { services: Service[]; integrations: Integration[];
                   dismissed: DismissedIntegration[] };
type ToolchainOperation = addService | updateService | removeService | addIntegration
                        | removeIntegration | dismissIntegration | restoreIntegration | splice;
parseToolchainOperation(raw);
// @keelson/toolchain
parseToolchain(text | null): { toolchain, diagnostics };
validateToolchain(toolchain, pipeline, tools): Diagnostic[];
applyToolchain(text, operation): Result<{ text, hash, toolchain, inverse, touched }>;
proposeIntegrations(pipeline, toolchain, tools): ProposedIntegration[];
analyseToolchain(text | null, pipeline, tools): { toolchain, diagnostics, proposed };
parsePositions(raw); writePositions(text | null, positions): string | null;
// @keelson/catalog
detectIntegrations(signals, tools): { tool, kind }[];
```

Routes, same guard as documents:

| Method | Route | Responses |
|---|---|---|
| GET | `/api/toolchain` | 200 `{ text, hash, toolchain, diagnostics, proposed, positions }` |
| POST | `/api/toolchain/operations` | `{ op, opId }` → 200 the same body plus `inverse` · 400 · 409 · 422 |
| PUT | `/api/layout/positions` | `{ positions }` merged into the file → 200 with the full map · 400 · 422 if `layout.json` is unreadable |

SSE: `toolchain.changed { hash }`.

## 6. Definition of done

1. Services and integrations read, validated, written by invertible operations, comments preserved.
2. Four fast-check properties on a corpus of files, at 500 runs.
3. Inference: proposed, confirmed, dismissed, never written on its own.
4. Toolchain view: graph, free positions persisted, keyboard-equivalent panel, DOM and E2E.
5. `keelson validate` covers the toolchain; `keelson coverage` counts services.
6. Gaps of §4 closed with proof.
7. `shape`, `critique`, `audit`, `polish`, `document` if the tokens change.
8. Independent review, counter-review, full verification, merge, log.

## 7. Interface scoping (`/impeccable shape`)

**Operate** mode. Visual authority: `DESIGN.md`, with no new token. The autopilot rules out
interactive validation: assumptions are flagged and settled here.

- **Job.** The platform engineer describes what surrounds the pipeline and reviews the diff of
  `toolchain.yaml`; the architect checks there what talks to what. Success: every inference
  proposal is confirmed or dismissed, and the written file reads well in review.
- **Fourth view**, between Pipeline and Coverage: it is material, not a report.
- **Left sidebar**: Proposed integrations first, since that is the pending decision, then Services,
  then Add service. Everything the graph does can be done there with the keyboard.
- **Canvas**: relevant jobs on the left, services on the right, free positions with the mouse,
  remembered in `layout.json`. A position is not information: no keyboard equivalent is owed, and
  the default placement stays legible. Assumption: no edge creation by drawing, the form is enough
  and the file stays the reference.
- **Edges**: solid and labelled with their type for an integration, dashed for a proposal, never
  colour alone.
- **Service panel on the right**: URL, environment, integrations, removal refused while a job is
  linked to it, with the reason. Overlay below `lg`, like the job panel (ADR 0008).
- **Coverage**: a layer covered by a service names it.
- **States**: no service, invalid file (editing disabled, the diagnostic says why), file changed on
  disk (reloaded, history cleared), proposal without a service (it pre-fills Add service), partial
  pipeline.
- **Undo** applies to the toolchain in its view, with the same controls as the pipeline.
