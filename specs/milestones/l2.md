# Lot L2 — serveur local, vue Pipeline et `keelson start`

Document de cadrage écrit à partir du code réellement livré sur `lot/l2-pipeline-ui`, les étapes 0 à
3 étant déjà faites au moment de sa rédaction.

## Objet

Rendre Keelson utilisable : `keelson start` lance un serveur local qui fait autorité sur le disque et
sert une UI web qui affiche et édite le pipeline. L'UI n'écrit jamais de fichier et n'exécute pas
l'adaptateur ; elle envoie des opérations.

## API du serveur

| Méthode | Route | Réponses |
|---|---|---|
| GET | `/api/workspace` | 200 `{ files: [{ path, adapter }] }` |
| GET | `/api/documents/:file` | 200 `{ text, pipeline, diagnostics, hash }` · 404 |
| POST | `/api/documents/:file/operations` | corps `{ op, opId }` → 200 `{ pipeline, diagnostics, hash, inverse, touched }` · 400 `INVALID_OPERATION` · 404 · 409 `STALE_DOCUMENT` avec le `hash` courant · 413 · 422 `{ code, message, details }` |
| GET | `/api/events` | SSE `document.changed { file, hash }`, `document.removed { file }` |
| GET | `/*` | bundle de l'UI, repli SPA sur `index.html` |

Toute erreur a la forme `{ code, message, details? }`. 403 avant tout traitement si l'en-tête `Host`
n'est pas `127.0.0.1:<port>` ou `localhost:<port>`, puis 403 si le token de session est absent ou
faux. Corps limité à 1 Mo.

## Modèle de sécurité

Écoute sur `127.0.0.1` seulement, sans option pour en changer. Token de 32 octets par session
(`node:crypto`), transmis dans l'URL ouverte (`?token=`), puis envoyé dans l'en-tête
`X-Keelson-Token` ; `/api/events` le prend en paramètre de requête, `EventSource` ne pouvant pas
poser d'en-tête. Comparaison en temps constant sur des digests SHA-256, donc indépendante de la
longueur. Les fichiers accessibles sont bornés à la liste détectée par le workspace : tout autre
chemin, `..` compris, rend 404.

## Étapes

0. ✅ `aria-describedby` à la place de `aria-description` sur les nœuds de job.
1. ✅ `tokens.css` et le garde anti-valeurs en dur.
2. ✅ Vue Pipeline : colonnes par stage, nœuds, arêtes, badges d'origine.
3. ✅ Panneaux : détail du job (blocs opaques en CodeMirror lecture seule), diagnostics avec
   `selectByRange`.
4. États : chargement, aucun fichier CI, YAML invalide (édition désactivée), fichier supprimé, et
   les trois `notice`.
5. Édition : créer / renommer / supprimer un job (`JOB_REFERENCED` liste les référents), changer de
   stage, ajouter et retirer un need, définir et retirer l'environnement, ajouter et déplacer un
   stage, undo/redo par boutons et par Ctrl/Cmd+Z et Ctrl/Cmd+Shift+Z. Chaque glisser-déposer a une
   alternative au clavier dans le panneau. Le `message` du serveur est affiché tel quel ; un 409
   recharge, vide les piles et dit que l'opération n'a pas été appliquée.
6. `app.tsx` : lecture du token dans `?token=`, retrait par `history.replaceState`, envoi en en-tête.
7. `scripts/dev.ts` et `bun run dev` : serveur programmatique sur `packages/ui/dev-fixture` avec un
   token fixe, Vite sur 5283 avec proxy `/api` qui ajoute l'en-tête.
8. E2E sur le binaire buildé lancé par `node` contre une copie temporaire de fixture :
   `pipeline.e2e.ts` (affichage, renommage vérifié sur disque, ajout d'un need, undo qui restaure les
   octets, modification externe qui recharge, 409 affiché) et `keyboard.e2e.ts` (toute action
   d'édition sans souris).
9. Impeccable : `critique`, `audit`, correction, `polish`, puis `document` qui écrit `DESIGN.md`.
10. Docs : `specs/01-plan.md` (API du serveur et modèle de sécurité), `CLAUDE.md` (`bun run dev`).
