# Milestone L2 — local server, Pipeline view and `keelson start`

Scoping document written from the code actually delivered on `lot/l2-pipeline-ui`, with steps 0 to 3
already done at the time of writing.

## Purpose

Make Keelson usable: `keelson start` launches a local server that is authoritative over the disk and
serves a web UI that displays and edits the pipeline. The UI never writes a file and never runs the
adapter; it sends operations.

## Server API

| Method | Route | Responses |
|---|---|---|
| GET | `/api/workspace` | 200 `{ files: [{ path, adapter }] }` |
| GET | `/api/documents/:file` | 200 `{ text, pipeline, diagnostics, hash }` · 404 |
| POST | `/api/documents/:file/operations` | body `{ op, opId }` → 200 `{ pipeline, diagnostics, hash, inverse, touched }` · 400 `INVALID_OPERATION` · 404 · 409 `STALE_DOCUMENT` with the current `hash` · 413 · 422 `{ code, message, details }` |
| GET | `/api/events` | SSE `document.changed { file, hash }`, `document.removed { file }` |
| GET | `/*` | UI bundle, SPA fallback to `index.html` |

Every error has the shape `{ code, message, details? }`. 403 before any processing if the `Host`
header is not `127.0.0.1:<port>` or `localhost:<port>`, then 403 if the session token is missing or
wrong. Body limited to 1 MB.

## Security model

Listens on `127.0.0.1` only, with no option to change it. 32-byte token per session
(`node:crypto`), passed in the opened URL (`?token=`), then sent in the `X-Keelson-Token` header;
`/api/events` takes it as a query parameter, since `EventSource` cannot set a header. Constant-time
comparison on SHA-256 digests, hence independent of length. Accessible files are limited to the list
detected by the workspace: any other path, `..` included, returns 404.

## Steps

0. ✅ `aria-describedby` instead of `aria-description` on job nodes.
1. ✅ `tokens.css` and the hard-coded-value guard.
2. ✅ Pipeline view: columns per stage, nodes, edges, origin badges.
3. ✅ Panels: job detail (opaque blocks in read-only CodeMirror), diagnostics with
   `selectByRange`.
4. States: loading, no CI file, invalid YAML (editing disabled), deleted file, and the three
   `notice`s.
5. Editing: create / rename / delete a job (`JOB_REFERENCED` lists the referrers), change stage, add
   and remove a need, set and remove the environment, add and move a stage, undo/redo by buttons and
   by Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z. Every drag-and-drop has a keyboard alternative in the panel.
   The server's `message` is displayed as is; a 409 reloads, clears the stacks and says the operation
   was not applied.
6. `app.tsx`: read the token from `?token=`, remove it with `history.replaceState`, send it as a
   header.
7. `scripts/dev.ts` and `bun run dev`: programmatic server on `packages/ui/dev-fixture` with a fixed
   token, Vite on 5283 with an `/api` proxy that adds the header.
8. E2E on the built binary launched by `node` against a temporary copy of a fixture:
   `pipeline.e2e.ts` (display, rename checked on disk, adding a need, undo that restores the bytes,
   external change that reloads, 409 displayed) and `keyboard.e2e.ts` (every editing action without
   a mouse).
9. Impeccable: `critique`, `audit`, fixes, `polish`, then `document`, which writes `DESIGN.md`.
10. Docs: `specs/01-plan.md` (server API and security model), `CLAUDE.md` (`bun run dev`).

- The Node smoke test covers `keelson start` on the built binary.

- `DESIGN.md` exists and matches `tokens.css`.
- `specs/01-plan.md` describes the server API and the security model; `CLAUDE.md` describes
